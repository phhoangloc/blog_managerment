# Repository Structure

The API lives under `/backend`.

```
backend/
├── prisma/
│   ├── schema.prisma          # admin, user, file models
│   ├── migrations/            # generated by `prisma migrate`
│   └── seed.ts                # creates the first admin from SEED_* variables
├── public/
│   └── upload/                # uploaded files (contents git-ignored, .gitkeep kept)
├── src/
│   ├── server.ts              # starts the HTTP server
│   ├── app.ts                 # builds the Express app (cors, json, static, router, errors)
│   ├── config/
│   │   ├── env.ts             # reads .env
│   │   └── prisma.ts          # PrismaClient instance
│   ├── routes/
│   │   └── index.ts           # composition root: wires repositories, services, controllers
│   ├── controllers/           # AuthController, AdminController, UserController, FileController
│   ├── services/              # AuthService, AdminService, UserService, FileService, FileStorage, AvatarResolver
│   ├── repositories/
│   │   ├── interfaces.ts      # entity types and I*Repository contracts
│   │   └── prismaRepositories.ts
│   ├── middleware/            # auth, validate, upload, error
│   ├── validators/
│   │   └── schemas.ts         # zod schemas
│   └── utils/                 # AppError, passwordHasher, tokenService
├── tests/
│   ├── services/              # unit tests for each service (repositories mocked)
│   └── middleware/            # unit tests for each middleware
├── .env / .env.example
├── jest.config.js
├── package.json
├── tsconfig.json
└── test.rest                  # manual HTTP requests
```

## Conventions
- One class per file, file named after the class (`UserService.ts`).
- A new entity adds: a Prisma model, an entity type and interface in `repositories/interfaces.ts`, a Prisma repository, a service, a controller, routes in `routes/index.ts`, zod schemas, and tests under `tests/services`.
- `.env` is never committed; `.env.example` lists every variable.

## Other top-level folders
```
docs/ideas/      # product ideas (input)
docs/spec/       # these specification documents
docs/steering/   # per-feature requirement, structure and task notes
plan/, task/     # initial plan and task list
```
